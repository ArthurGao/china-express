# 10 测试与验收

“覆盖率 100%”和“与原型一致”都不能证明收费正确。测试以**签字后的决策表**为依据；原型和交接说明的算例只是输入之一，
不一致时请业主裁决并修正算例。

## 分层

| 层 | 工具 | 内容 |
| --- | --- | --- |
| 报价引擎单元 | Jest（backend） | 04 的算例、边界、每个 DECISION 的两种取值（用配置切换） |
| 状态机单元 | Jest | 每个允许 / 不允许的迁移、角色、前置条件、回退写审计 |
| API 集成 | Jest + Testcontainers Postgres + 伪造 JWT | 权限、字段白名单、幂等、乐观锁、并发 |
| 前端组件 | Vitest + Testing Library | 表单校验、i18n 完整、内置浏览器提示 |
| 端到端 | Playwright | 主流程，手机视口；第 2 阶段客户 + 仓库双浏览器 |
| 弱网 | Playwright 网络节流 + 仓库实地 | 入库重提交、照片重传、SSE 重连 |
| 恢复演练 | 手工脚本 | 从备份恢复后核对货件、照片关联、收款 |

## 第 1 阶段验收

- [ ] 计价：10 / 20 / 25 / 100 kg、1 m³、1.5 m、货值三档边界各一组，结果与签字后的附件一一致；方向性按 C1 选定规则测。
- [ ] 服务端独立计算：篡改请求中的重量、金额或费率参数不改变服务端结果（含 FCL）。（需真实后端；前端只显示 API 结果，
  由组件测试和静态守卫覆盖）
- [ ] 快照：发布新费率版本后，历史报价的数值和版本号不变。
- [ ] 价格发布：只有 admin 且已 MFA；有操作人和前后值审计。
- [ ] 登录：iPhone 和安卓从 WhatsApp、Messenger、Facebook 打开链接都能完成登录；转发诱导登录用例被拒绝（若实现反向验证）。
- [ ] 账户：已有身份不会被自动合并；账户恢复流程可走通。
- [ ] 预报：未确认禁运品告知不能提交；仓库地址含正确会员号。

## 第 2 阶段验收（含试运行前置）

- [ ] 并发：两名员工同时操作同一包裹，不会重复入库、重复合并或重复出库。
- [ ] 防重：同一件重复扫码只提示不新建；一单多箱按件序号正常收货；断线重提交不产生重复记录。
- [ ] 权限：客户看不到其他客户的货件和照片；仓库账号的响应里没有完整电话和地址。
- [ ] 实时：在仓库实际网络下，入库提交后 5 秒内客户端可见；一次合并作业能算出最终价。
- [ ] 账务：重复收款确认不重复记账；冲销和退款都有操作人、时间、凭据；发票更正不改原发票；未足额放货需审批。
- [ ] 通知：重复事件不重复发送；失败可见可重试。
- [ ] 试运行前置：最小安全与权限检查通过；自动备份 + 一次恢复验证；告警 5 分钟内送达；服务、隐私、退款、货物处理条款已上线；生产负责人和故障处理办法已确认。
- [ ] 界面：客户界面全英文，仓库界面全中文。

## 第 3 阶段验收

- [ ] 支付：重复、乱序、超时回调不重复记账也不漏记；每种方式成功、失败、退款各一遍。
- [ ] 对账：网关结算、平台收款、Xero 三方一致，差异进财务待办。
- [ ] 扩展：管理员改一个费率，所有渠道报新价；新区域不改代码上线；FCL 运价过期后停止出数。
- [ ] 压力：报价接口 50 请求/秒下 p95 < 500 ms；入库高峰不丢请求。
